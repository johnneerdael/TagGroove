# UI translations and Options → Language — 2026-10-16

Branch `feat/i18n`, started from `feat/core-parity` at `11ba278`. It covers the Options → Language row of `docs/research/remaining-gaps.md`. OpenTag ships its own catalogs: English, Dutch and German. Mp3tag's `.lng` files are proprietary. They were not read, copied or used as a source, and nothing in the catalogs comes from them.

No desktop application was launched for this review follow-up. Local evidence comes from the catalog/core tests and DOM-backed production-renderer tests described below. The native suite `tests/e2e/i18n.js` is configured in the CI `native-e2e` job on Linux, macOS and Windows; its presence is not a claim that the updated head has completed a desktop replay.

## How it works

| Part | Where | What it does |
|---|---|---|
| Catalogs | `src/i18n/catalogs/{en,nl,de}.json` | Keys are the English text as the UI shows it. `{name}` marks a value filled in at run time (`"Saved tags: {saved} files"`). `@meta` names the language. `@keys` holds local names of keyboard keys (German: Ctrl → Strg, Shift → Umschalt, Del → Entf). |
| Core | `src/i18n/core.ts` | `Translator.t(key, params)` fills a key. Values may choose a form by number with `{count, plural, one {# file} other {# files}}`, using `Intl.PluralRules` categories or `=N`. `translate(text)` takes rendered English text and finds its key, either exactly or as a pattern whose values it reads back from the text. Values that are UI text themselves (a nested "3 files" or a known error message) are translated too. Names of files, folders and values are left as they are. Values named as counts (`{count}`, `{length}`, `{size}`, …) match only digits, so a key such as "{count} files" never captures other text. `validateCatalog` and `resolveLanguage` are here as well. |
| DOM layer | `src/i18n/dom.ts` | A `MutationObserver` on `document.body` translates text nodes and the attributes people read (`title`, `aria-label`, `placeholder`, `alt`, `label`, `data-hint`, button `value`) as they are rendered. It remembers the English source of each node, so switching language is live in both directions. Observed application text/attribute writes invalidate that source record even if the value equals the prior translated output. Translator-owned writes suppress only their own mutation record, and synchronous apply/translateNow boundaries consume queued application writes before replaying remembered sources. Subtrees marked `translate="no"` are skipped: file/tag value spans and their titles, search results, the values in combo-box lists (their headings, Open folder… and No values are translated), saved history names/formats/descriptions, web source names, the location path, and every name someone gave (see below). An element marked `data-verbatim="<name>"` keeps that name as it is in its text and attributes, even when the name equals a key, while the sentence around it ("Show {name}") and any other text on the element are still translated. File-row checkboxes and pending-change tooltips, and history controls and empty states, remain outside the data exclusions. Cell-editor accessible labels consume the same final columnName display as headers, protect that label value while translating the Edit scaffold, and refresh marker/label together on reattachment without discarding typed text or selection. Provider URI/name leaves stay verbatim, while missing-source fallbacks translate in the pane and location header. Tag-source dialogs use aria-labelledby with a dedicated source-name leaf across search/review/Back: authored web names remain raw, built-in labels translate, and review artist/title values remain separate data leaves. Local headers carry explicit location provenance, preserving real paths even when they match a UI phrase while translating generated empty/added/dropped-location labels. Initial and forwarded desktop launches carry the same explicit role, derived from single-directory/shared-parent versus generated multi-location branches; producer and real host/header/title regressions cover both. Popup hosts call `translateNow` on newly inserted menus before reading their dimensions, including row/header/cover/field menus, helper submenus and tag-panel popups; the optional callback keeps standalone English component consumers independent. Form values are never changed. Textarea attributes translate while their editable text/default values remain verbatim. Source-defined settings choices retain their displayed tokens and explicit option values, so reading and saving a selection cannot store its translation. Bundled English installs no observer; an active user English catalog does. |
| Native boundary | `src/i18n/dialog.ts`, `src-tauri/src/tray.rs` | Native dialogs get translated titles, messages, file-type names and Yes/No/OK/Cancel labels. Callers keep passing English, so code that compares titles still works. Multiline `ask` messages can pass `{parts, separator}`: each source part is translated exactly once, then joined with its code-owned paragraph or line breaks. Remove Tag and Load Configuration use that path; output that equals another catalog key is not translated again. The window title and the tray icon menu (Show/Quit OpenTag) follow the language. Title formatting consumes explicit location provenance: generated labels translate once before entering the verbatim title scaffold, actual paths remain raw, and original empty-state visibility is decided before translation. Production syncWindowTitle/setTitle wrapper regressions cover DE/NL and custom English output collisions, same-spelling raw paths, whitespace, hidden-directory preference and cache deduplication. |
| Language choice | `src/i18n/index.ts`, `src/language-options.ts` | Options → Language offers "System default (…)", English, Deutsch, Nederlands and any user catalog. The choice is stored in `settings.json` (`pages.language.language`), so the configuration backup carries it. The system default uses the first preferred system language that has a catalog: exact match, then base language (`nl-BE` → `nl`), else English. The `System default ({nameOf})` scaffold translates while the catalog's declared display name remains verbatim; the existing catalog key is unchanged. Authored user option labels have a per-choice data marker, so a catalog named System default stays raw independently of the real system-default option. Explicit saved locale choices resolve by exact locale (case-insensitive) or English, while only system choices use regional/base-language fallback. The Language select keeps an unavailable saved locale as an explicitly selected translatable UI option naming the raw locale and effective English; leaving it untouched preserves the preference, while selecting real English uses the normal change/save path. The choice is also kept in local storage, so the first paint after a restart is already in the right language. |
| User catalogs | `src-tauri/src/languages.rs` | `<configuration folder>/languages/<locale>.json` adds a language or replaces a shipped one (`nl.json`). Options → Language → Open languages folder writes `_template.json` with the current English source values, an empty display name and no locale metadata. Copying it to `fr.json` or `pt-BR.json` derives the locale from that filename after its name and values are edited. Explicit locale metadata in other user catalogs remains supported. The folder-opening control starts hidden and is enabled only by an actual native desktop runtime report; Android, iOS, browser preview and unknown/report-failure states do not expose it. The production Language page and actual runtime callback regression cover those states and retain the desktop template payload, without a mobile device replay. The folder is read at startup and on every Options OK. Only a completed directory listing replaces the previous set; enumeration or candidate-file metadata failures propagate through the command, and the existing frontend catch reports a warning while retaining the current registry. NotFound still returns a successful empty snapshot. Individual file read/size/JSON failures remain reported in the snapshot errors. Each successful read replaces the previous set: a deleted or broken file is no longer offered, a removed `nl.json`/`de.json` brings the shipped catalog back, and an explicitly chosen language that disappeared falls back to English (the System default choice follows the preferred system languages). An `en.json` there replaces the shipped English everywhere, native dialogs and the tray menu included; editing an active file and choosing OK updates the tray labels as well. Missing keys show English. A key whose placeholders do not match the English key is dropped, so it shows English. The Language page lists files with problems. |
| Extraction | `scripts/i18n-extract.mjs` | Parses `src/*.ts` with the TypeScript compiler. It collects text nodes and UI attributes from markup templates, plus prose string literals, while skipping selectors, identifiers, comparisons, storage keys, format strings, mnemonics and shortcut labels. Conditionals with literal branches are expanded (`file${n===1?'':'s'}` gives "file" and "files"). A statement marked `// i18n-ignore` is left out; the genre list uses this because genres are tag values. `src/i18n/extra-keys.json` adds keys that do not appear as literals (plural helpers, tray labels, user-catalog warnings, verbs the backend inserts). `--write` regenerates `en.json`. |
| Backend messages | `src/i18n/backend-keys.json` | A snapshot of the user-facing error and status texts of the Rust commands (`Err(…)`, `ok_or(…)`, `map_err(… format!(…))` outside test modules), with `{}` values as placeholders. They are translated at the UI boundary: the DOM layer and the dialog wrapper match the message text like any other key. `node scripts/i18n-extract.mjs --backend` refreshes the snapshot. |

### Adding or changing UI text

1. Write English in the code as before.
2. Run `node scripts/i18n-extract.mjs --write` (or `npm run i18n:extract`). `tests/i18n.test.mjs` fails until `en.json` matches the code.
3. Add the new keys to `nl.json` and `de.json` with the same `{placeholders}`. The test also fails while any catalog lacks a key or has a placeholder mismatch.
4. Text that is data, not UI (tag values, file names, results from a tag source), goes in an element with `translate="no"`.
5. Code must not compare rendered text, because in another language it is translated. Compare state or `data-*` attributes instead. This branch changed the two places that did: the Convert menu focus (`data-menu`) and the Extended tags mixed-value marker (`data-mixed`).
6. Pass multiline native questions as English `{parts, separator}` to `ask` (or through `Messages.confirm`). Keep source values inside the relevant part, and let the native wrapper translate each part once. Do not pretranslate a string and send it through the translating wrapper.

## Decisions

- **The UI is translated where it is rendered.** The code keeps rendering English, and the DOM layer swaps the text. This avoids rewriting about 9,000 lines of template literals while dozens of parallel branches edit the same files. It also keeps every existing native suite valid, since they select by English text and run in English. `t()` is available for new code that needs a translated string outside the DOM; the tray labels use it. The extractor and the completeness tests keep the catalog honest the way a `t()`-everywhere approach would.
- **Live switching.** Mp3tag applies a language after a restart. OpenTag applies it when Options closes with OK. The DOM layer re-translates from the remembered English sources, and the main window renders again.
- **Backend text is matched, not coded.** Backend errors are plain strings today. Instead of adding error codes to every command, the catalog holds the message texts as patterns. That covers the existing messages without touching about 50 Rust modules. Error codes would make the match exact, but they are a larger change.
- **Not translated:** format strings, `%placeholders%`, scripting functions, field names (TITLE, ARTIST, …), genre names, file names and paths, tag values, and names someone gave: columns, tag panel labels, action groups, selection presets, tools, renamed toolbar items, export configurations, freedb servers, favourite and recent directories, saved format strings, cover descriptions, provider document names and web sources. A column named "Help" stays "Help" in German while the Help menu reads "Hilfe". These names are rendered inside `translate="no"` or with `data-verbatim`. Export duplicate-name errors use the authored `{name}` role rather than the incidental variable name `{trimmed}`; production Export dialog rename/error/save tests preserve conflicting names and unchanged libraries under DE/NL/custom catalogs. Toolbar hints use the underlying tool/action name as an authored parameter independently of a renamed display label. Hover/focus status renders original hint/reason source parts once and restores the original status nodes; regressions cover DE/NL/custom-English output collisions and newline names. Unknown multiline text under partial catalogs remains raw rather than failing the mark/arrow fallback. Technical {key} parameters remain raw in field, helper-list and configuration diagnostics; the separate @keys shortcut labels still localize. A real mixed TagPanel keep choice runs the production keepField/updateDraft functions, restores each loaded value, retains unrelated pending edits and translates its status under DE/NL/custom English. Related settingsError producers and shortcut labels are also checked. Mapping-validation producers use a translatable generated row label and a raw field-identifier role across all five error branches; actual Options validation/correction/save regressions cover DE/NL/custom catalogs. Favorite and included-directory option leaves keep restored relative paths, star prefixes and whitespace raw through selection/reorder/add/remove/save, beside translated list labels and controls. Preset removal options preserve the same raw names and values as the main preset selector. Both tool selectors toggle their marker before live name writes; clearing a name restores the translatable generated Tool N fallback. Production dialog/Options save regressions cover removal, cancel/reopen, blank/nonblank edits, selection redraws and raw persisted names under DE/NL/custom English. Freedb server list options toggle their data marker before each live name update; empty names use the translated Unnamed server fallback, and nonempty names remain raw even if equal to that fallback. Only a default column or tag panel field that still has its shipped name ("Title", "Tit&le") follows the UI language; renaming it, even to a UI word, keeps the typed name. The tag panel keeps its configured Alt letter and underlines it where the translated label contains it.
- **Web sources (.src)** keep their own names. Their settings dialogs use the UI language to pick the source's own localized prose. Headers, accessible names, headings, setting titles/descriptions, choices and defaults remain as authored, including their casing; fallback source titles and keys are data too. Result columns from `[IndexFormat]` and authored `[SearchBy]` labels retain their spelling/case; built-in provider headers and backend-synthesized default search labels follow the application catalog. A backend ownership flag distinguishes generated labels from identically spelled authored labels. URLs, cover-type descriptions and the cover filename template remain data-only leaves alongside translatable Preview and cover controls. Only OpenTag-owned Save/Cancel controls, the empty-settings message and validation/error scaffolds follow the application catalog. Numeric errors retain the visible source-localized field title.

Custom catalogs currently keep the document's default left-to-right direction:
`setLanguage` updates `lang` but does not set `dir`. Arabic/Hebrew catalogs do
not provide mirrored RTL controls, menus or navigation. The Language guide and
reference record this layout limitation alongside the text-translation feature.

## What remains English

- **Backend messages added after the snapshot.** The messages of `backend-keys.json` are translated, and a regression checks that its extracted Rust producers match the current merged source. A Rust message added later must be extracted with `--backend` and translated before that check passes. Parts of a message that come from the operating system or a library (an `io::Error`, a parser error) stay as they were produced, inside the translated sentence.
- **Operating system text.** File-system errors, the system file pickers' own buttons and the macOS application menu that Tauri creates are left to the operating system. The app bundle declares only English, so macOS shows that menu in English.
- **Developer-facing errors**, such as invalid options page identifiers. They are in the catalog, but users should never see them.
- **The test-only backend messages** (injected failures, fixture providers) are left out of the snapshot on purpose.
