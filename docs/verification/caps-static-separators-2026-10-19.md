For caps/caps2, omitted argument two selects the single-space string at file
offset `0x931270`. An explicit argument replaces that string, including an empty
one. The helper compares the current character with lower/upper forms of each
trigger; there is no separate whitespace classifier. Caps3 instead defaults to
an empty trigger string and uses exact membership with distinct first-character
and immediate-after-trigger rules. The [official interface description](https://docs.mp3tag.de/scripting/)
also distinguishes caps/caps2 trigger characters from caps3's additional triggers.

## Implementation and checks

The existing Rust helpers now select the effective trigger set explicitly.
Caps/caps2 use ASCII-insensitive membership, preserve a trigger at a word start,
and retain their different treatment of interior case. Caps3 keeps its separate
exact-match state machine, including first/consecutive triggers and no skipping
of whitespace after punctuation. Ordinary Rust Unicode case conversion and the
existing one-or-two-argument validation remain intact; no unsafe UTF-16 or CRT
emulation was introduced.

The real public evaluator first fails all three family regressions on the old
implementation, while arity and safe-Unicode controls pass. After repair, all 43
static-derived vectors and the unchanged controls pass. The focused scripting
and executable LF/CRLF guide suites pass 54 tests. Independent code and native-
evidence reviews are clean. The combined workspace then passes 1,340 Rust tests
with 18 ignored and zero failures, plus 825 frontend tests. Strict workspace/
all-target Clippy, formatting, production build, catalog and guide checks pass.

These results establish the implemented contract against bounded static ASCII
predictions. They do not establish original runtime output, locale-dependent CRT
behavior, Unicode/UTF-16 equivalence, malformed-input/error behavior or public
extra-argument results. L08 retains those comparisons; L09 truth propagation and
L10 errors are unchanged. Native GUI, Windows and final hosted review/CI remain
separate acceptance work.
