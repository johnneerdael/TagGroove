## Execution contract

| Stage | Work |
| --- | --- |
| Before ordinary PR merge | Authenticated exact-head Codex code review, substantive release notes, then one Linux worker for frontend/Rust unit tests, TypeScript checks, formatting, Clippy, tooling and strict documentation checks. |
| After merge | Release packages, desktop native UI, screenshots and Android integration. Native integration and all required packages/source checks must pass before application publication. |
| Main build repair | Owner-authorized single-parent repair of the failed source, with a `CI-Repair-Run` trailer. The referenced trusted release must have passed authorization and preparation before failing. The gate rechecks source ancestry and repair evidence before publication. |

The pre-merge status retains its historical `Reviewed PR builds` name for branch protection. Tests compile test binaries; pre-merge CI does not package applications. Native UI requires a debug harness with its own test identity, separate from shipping packages. Post-merge jobs do not repeat pre-merge unit/lint/documentation test suites. The frontend test glob already includes the release tests, so their duplicate explicit invocation was removed. Desktop matrices and native suite loops stop on failure.
