# Local documentation preview receipt

Preview source: the combined `codex/guide-expansion` branch after the initial
publication newline fix and shared example parser. The generated static site
was served on localhost. No application was launched and no public deployment
was performed.

## Verified in Chrome

- Desktop dark mode: home, the format-string beginner lesson and native mapping
  tables. Tutorial navigation and the eight-step table of contents were legible.
- Desktop light mode: the format-string lesson, examples and practice checklist
  remained legible; the document width and scroll width were both 1728 px.
- Navigation: the format-string reference is a direct reference entry, with
  scripting functions in a separately named group. This avoids Material's
  section-index behavior linking the format-string label to the function index.
- Search: the default separator returned no result for `fmtdate`. After adding
  format-string punctuation to the separator, the same query returned three
  documents: Dates and durations, Placeholders, and Scripting functions. The
  date-function result linked to its individual function anchor. The broader
  `format` query also returned indexed guide content.
- At 390 × 844 px: the tutorial text, prerequisites and inline code wrapped
  within the viewport. The document width and scroll width were both 390 px.
  The navigation drawer opened and displayed the current lesson and its sibling
  tutorials without clipped labels.
- Native mapping identifiers remain intact rather than breaking in the middle
  of a field name. At 390 px, both focusable table regions were 358 px wide,
  with content scroll widths of 1408 and 1039 px. The outer page stayed within
  the viewport. Desktop table overflow was likewise confined to the table.

## Limits

The browser automation timed out during the keyboard-scroll check. A focusable
region and bounded horizontal overflow were confirmed, but keyboard scrolling
was not verified. The temporary viewport override was reset afterward.

This was representative documentation QA, not an inspection of all 75 pages
at every breakpoint. It does not establish application runtime behavior,
native-format write support, original-application parity or live Pages status.
Recheck affected views after integration changes.
