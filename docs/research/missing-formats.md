# Missing format backend research

Research checkpoint: 2026-10-14. No dependencies, bridge, or format implementation were added. Only small public upstream source files were inspected outside the application. Original Windows runtime comparison is still missing; library format support does not establish Mp3tag parity.

Recommend a narrow C++17 TagLib bridge for ASF/WMA and DSF/DFF as the next proof spike, retaining Rust orchestration and the existing Lofty paths. Pin TagLib **2.3.2**, commit `deadc2990767dfbda0701e0ab35fdeea653db08f` (the signed v2.3.2 tag resolves there). The [official release](https://taglib.org/) includes WMA improvements and malformed-input hardening across these formats. Do not use the generic PropertyMap as the canonical metadata model: keep the existing Mp3tag field registry in Rust and expose native typed attributes/frames through a small C ABI. A complete independent Rust ASF writer would duplicate complex typed/multilingual/multistream object handling before delivering the missing formats; a bounded Rust object scanner is useful immediately as an independent preservation verifier.

| Format | Concrete upstream API | Preservation constraint |
| --- | --- | --- |
| ASF/WMA | `ASF::File::tag()`, `audioProperties()`, `save()`; const `ASF::Tag::attributeListMap()`, `attribute()`, `setAttribute()`, `addAttribute()`, `removeItem()` | Content Description title/author/copyright/comment/rating are separate members, outside attributeListMap. Handle them explicitly. Attributes retain native types, stream and language numbers. |
| ASF artwork | `ASF::Attribute::toPicture()` / picture constructor; `ASF::Picture` MIME, type, description, byte payload | WM/Picture supports repeated attributes. Preserve all unaddressed attributes; do not replace the entire generic picture property for an individual edit. |
| DSF | `DSF::File::tag()` yields ID3v2; `save(ID3v2::Version)` | Default save uses v2.4. Preserve the requested original version explicitly. The writer replaces the metadata tail and can truncate trailing bytes. |
| DFF/DSDIFF | `ID3v2Tag()`, `DIINTag()`, `hasID3v2Tag()`, `hasDIINTag()`; parameterized save | ID3 can be root-level or inside PROP; DIIN also contains title/artist. Use explicit tag mask, `StripNone`, and version. Save removes duplicate PROP ID3 chunks, so duplicate-container fixtures need rejection or special handling before enabling writes. |

Primary API/source: [ASF file](https://github.com/taglib/taglib/blob/v2.3.2/taglib/asf/asffile.h), [ASF tag](https://github.com/taglib/taglib/blob/v2.3.2/taglib/asf/asftag.h), [typed attributes](https://github.com/taglib/taglib/blob/v2.3.2/taglib/asf/asfattribute.h), [pictures](https://github.com/taglib/taglib/blob/v2.3.2/taglib/asf/asfpicture.h), [DSF writer](https://github.com/taglib/taglib/blob/v2.3.2/taglib/dsf/dsffile.cpp), [DSDIFF writer](https://github.com/taglib/taglib/blob/v2.3.2/taglib/dsdiff/dsdifffile.cpp).

Source inspection shows that ASF unknown GUID objects retain raw payloads, while known attribute objects are rebuilt and attributes are redistributed according to size/type/stream/language. Unknown attribute *names* can retain typed values; unknown wire *type codes* are not a preservation guarantee. Generic properties translate names and deduplicate equal values. The ID3 serializer has extended-header/footer TODOs, drops tag-alter-preservation frames, and downgrades version-specific frames. Staging plus successful `save()` is insufficient: compare unedited native values, opaque payloads and media ranges after reopening. Relevant source: [ASF save](https://github.com/taglib/taglib/blob/v2.3.2/taglib/asf/asffile.cpp), [ASF generic conversion](https://github.com/taglib/taglib/blob/v2.3.2/taglib/asf/asftag.cpp), [ID3 rendering](https://github.com/taglib/taglib/blob/v2.3.2/taglib/mpeg/id3v2/id3v2tag.cpp).

Build the bridge statically with PIC, hidden symbols and C++17, enabling WITH_ASF and WITH_DSF and disabling unrelated optional formats/bindings/examples/tests. WITH_DSF includes DSDIFF; MPEG/ID3 remain mandatory upstream components. Required utf8cpp and optional zlib must be pinned explicitly; keep zlib available if compressed ID3 preservation is required. TagLib's file headers offer LGPL-2.1 **or MPL-1.1**; selecting MPL requires retained notices/license and covered-source availability, rather than relabeling upstream code MIT. The MIT application and independently authored bridge remain separate. See [build options/dependencies](https://github.com/taglib/taglib/blob/v2.3.2/INSTALL.md), [CMake](https://github.com/taglib/taglib/blob/v2.3.2/CMakeLists.txt), and [MPL text](https://github.com/taglib/taglib/blob/v2.3.2/COPYING.MPL).

The upstream install guide documents Android NDK cross-compilation, but its normal CI does not prove our mobile targets. Use the same pinned NDK/API/libc++ choice as the existing Boost bridge; avoid combining CMake's default static libc++ with a separately linked shared runtime. For iOS, build separate iphoneos and iphonesimulator archives with explicit SDK, deployment target and architecture; do not reuse a macOS archive. Run actual final application links for Android arm64, iOS device arm64 and simulator arm64, plus Windows MSVC and both desktop architectures. Compile success is not device I/O qualification. Primary constraints: [Android C++ runtime rules](https://developer.android.com/ndk/guides/cpp-support), [CMake Apple cross-compilation](https://cmake.org/cmake/help/latest/manual/cmake-toolchains.7.html#cross-compiling-for-ios-tvos-or-watchos).

First implementation scope: native reads and typed snapshots for the three container families; patch/remove known and custom fields through native APIs; individual cover operations; Rust sibling staging and permissions/race checks; bounded native-header preservation verification; unchanged ASF Data/Index objects, DSF sample-data and DFF DSD/DST chunks. Use disposable generated WMA and specification-derived DSF/DFF fixtures, including large pictures, repeated values, every ASF type, nonzero language/stream, unknown GUID objects, opaque ID3 frames, extended headers, duplicate ID3 placements, odd chunk padding and sparse files over 4 GiB. Do not silently enable writes on fixtures whose untouched data fails the verifier.

Unresolved original semantics: all 40 ASF mappings and custom-field spelling/types; repeated-content-field behavior; rating/Boolean/GUID/timestamp text forms; language/stream selection; malformed-art exposure; DSF/DFF preferred ID3 version and placement; DIIN-vs-ID3 precedence and synchronization; duplicate-ID3 policy; ID3 extended-header/flag handling; ASF header-size/file-size and index consistency after growth; trailing data preservation; DSD technical labels and sample-count interpretation; SAF/security-scoped document save-back. These require native original-app/runtime and device evidence.

Format basis: [Microsoft ASF structure](https://learn.microsoft.com/en-us/windows/win32/medfound/asf-file-structure), [Sony-authored DSF 1.01 specification, hosted mirror](https://dsd-guide.com/sites/default/files/white-papers/DSFFileFormatSpec_E.pdf), [Philips-authored DSDIFF 1.5 specification, hosted mirror](https://www.sonicstudio.com/pdf/dsd/DSDIFF_1.5_Spec.pdf). DSF has a little-endian metadata pointer and terminal ID3v2 region; DSDIFF uses big-endian 64-bit chunk sizes and even-byte padding, with native edited-master information. No vendor specification body is redistributed here.
